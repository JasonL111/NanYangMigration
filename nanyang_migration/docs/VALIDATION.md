## 根因与执行链

RC1 的用户截图显示：832 个来源 POP，来源人口 337,827,747，各区有效实际州 5 / 32 / 3 / 13 / 7 / 12，同时本次调用与请求量为零。这把问题缩小到来源和目的地枚举之后、第一次原生移动之前。截图没有单步引擎日志，无法证明是哪个条件或绑定最先挡住请求。RC2 用原生 State/POP 枚举、生成器写出的固定调用及按存在性判断的停止标记，替换此阶段的临时列表、列表参数和布尔值比较。再检查每笔额度和来源标记，避免迭代期间状态改变造成并行抽取或重复迁移。

RC2 的后续实机截图显示 18 个格子启动、225 个目的州份为正，但配对和原生调用均为零。用户随后提供的 error.log 明确报 `has_variable trigger [This scope doesn't support variables]`，列出士兵、职员、农民和劳工等 POP，指向 `nanyang_effects.txt:403`。该位置与 RC2 中 `every_scope_pop` 的 `has_variable = nym_available` 一致。实机日志确认了这条筛选失败，不能用生成作用域表的声明覆盖。

RC4 移除了 RC3 仍残留的人口对象变量读取、写入、余额扣减和清理。迁移前核对目的州接收标记。接收过某文化的州当次不能转出该文化，避免把新到 POP 或与它合并的人口再次转移。原有人口也可能因此少迁，其他文化不受阻挡。模拟器收到任何 POP 变量操作会主动报错。同一玩家场景的模型在正式版中核验首航为 200,000 人。另验证国内同文化不重复迁移、其他文化仍可迁出、接收标记不能写入时不调用引擎，以及标记在结束时清理。

1.0.0 的上下界误用和旧模型的同类误读已经确认。1.0.1 修完上下界后，反馈仍然失败。在 1.0.2 确定能从代码确认的缺陷是“把未验证即时州差值当成失败并允许再次发起”。该路径既可能发生在请求零移动时，也可能发生在移动已执行但统计尚未更新时。反馈没有附该版本的原生日志或分阶段读数，无法确定最初停在哪一环。新版的旧日志字段不兼容是另一个可确认的问题，与 1.13.11 的原始报告分开处理。

执行链为 Journal → Button（玩家/中国资格与全局冷却/锁）→ 锁定 → Country POP 规模统计 → 每个 State Region 的实际州 → 文化×地区额度并在州间均分 → POP 内原生效果 → 通过保存的两个州重新求同文化合计 → 核对守恒且不超过请求 → 完成结算，或停止挂牌待确认。源对象被消耗后，正式脚本不读取其迁出后的大小。本国州接收标记在操作结束清除。外州接收标记在一天后到期。已有成功/冷却/历史变量保留。

最优先的待验证假设是跨国移动的参数绑定和单位、同调用链的统计/对象刷新。独立探针在一次测试周期内覆盖常数、动态值、比例、全 POP 四种请求，以及两端合计/缓存/原对象的即时与翌日读数。翌日正常人口变动可能混入结果，不能用于正式自动结账。原生操作没有已知返回值或回滚，无法确认的操作锁只随回档解除。详细原生行为尚未全部实测。

迁移开始时统计本国来源人口，地图遍历收窄为 30 个设计地理域。每个文化和目的州的有效份额以原生 Country POP 枚举筛选来源。每次实际调用另扫两州各两次，换取相互独立的核验读数。若有 P 个本国 POP、D 个目的实际州、K 次调用，由于文化数固定，配对扫描量级为 O(P·D)，核验成本取决于每笔涉及的两州 POP 数。没有轮询或无界重试。未测得实际游戏耗时。

## 根因与执行链

1.0.0 的上下界误用和旧模型的同类误读已经确认。1.0.1 修完上下界后，反馈仍然失败。在 1.0.2 确定能从代码确认的缺陷是“把未验证即时州差值当成失败并允许再次发起”。该路径既可能发生在请求零移动时，也可能发生在移动已执行但统计尚未更新时。反馈没有附该版本的原生日志或分阶段读数，无法确定最初停在哪一环。新版的旧日志字段不兼容是另一个可确认的问题，与 1.13.11 的原始报告分开处理。

执行链为 Journal → Button（玩家/中国资格与全局冷却/锁）→ 锁定 → Country POP 快照 → 每个 State Region 的实际州 → 文化×地区额度并在州间均分 → POP 内原生效果 → 通过保存的两个州重新求同文化合计 → 核对守恒且不超过请求 → 完成结算，或停止挂牌待确认。源对象被消耗后，正式脚本不读取其迁出后的大小。清理由原始列表和对象存在检查决定。已有成功/冷却/历史变量保留。

最优先的待验证假设是跨国移动的参数绑定和单位、同调用链的统计/对象刷新。独立探针在一次测试周期内覆盖常数、动态值、比例、全 POP 四种请求，以及两端合计/缓存/原对象的即时与翌日读数。翌日正常人口变动可能混入结果，不能用于正式自动结账。原生操作没有已知返回值或回滚，无法确认的操作锁只随回档解除。端到端目标尚未验证。

迁移开始时扫描本国 POP 一次，地图遍历收窄为 30 个设计地理域。分配使用文化分组列表。每个目标州最多扫描一次对应文化的来源快照；每次实际调用另扫两州各两次，换取相互独立的核验读数。若有 P 个来源 POP、D 个有效州、K 次调用，分配扫描上界为 O(P·D)，核验成本为 O(Σ每笔涉及两州的 POP 数)。没有轮询或无界重试。未测得实际游戏耗时。
